# 清晰度和矢量源文件

> 业主的要求(11 月 16 日):注意清晰度,最好原画级别;所有美术素材都要有一份矢量源文件,
> 最好分层、拆好元素。让去 GitHub 上找现成的方案。这份文档写的是找到了什么、用了什么、做到什么程度。

## 1. 结论

| 要求 | 现在的做法 | 做到的程度 |
|---|---|---|
| 清晰 | 每张母版用二次元专用的放大模型放大 4 倍,仓库里存 2 倍的高清版 | 线条、睫毛、发丝比直接拉大清楚得多;运行时的立绘从 720 宽提到 1080 宽 |
| 矢量源文件 | 每张母版自动拆层、描成路径,存成分层的 SVG | 每张都有;能在 Inkscape、Illustrator、Figma 里按层打开、改色、挪动 |
| 分层拆元素 | 人物:背景、服装、暗部与线条、皮肤、五官、头发、霓虹光七层(戴头盔的是「头盔与面罩」);场景两层;图标两层 | 头部是模型认的,其余靠颜色和位置,**边界不完全准**,见第 4 节 |

需要说清楚的一点:**这是从位图自动描出来的矢量,不是手绘的矢量稿。** 渐变被描成一圈圈色块,放得很大时能看出来。
它的用处是给美术一个能直接上手改的起点,和「每张图都有可编辑的源文件」这个流程要求对上;
要真正的原画级矢量,还是得有人在这个基础上重描关键部位(脸、手、轮廓)。

## 2. 文件在哪

```
art/biao/masters/   母版:出图工具给的原图。人物和竖的场景 832×1216,横的场景 1216×832
art/biao/hires/     高清版:放大 4 倍后缩到 2 倍(1664×2432 或 2432×1664)
art/biao/vector/    矢量源文件:每张一个分层 SVG;layers.json 记着每层的面积和路径数
assets/biao/        运行时用的图,从高清版裁出来;其中的 .svg 是图标,本身就是矢量源文件
.work/art/up4x/     4 倍的原始结果(3328×4864,每张十来兆,不进仓库,重跑工具就有)
```

三类素材的矢量源文件分别是:

| 素材 | 矢量源文件 | 怎么来的 |
|---|---|---|
| 人物立绘(8 位角色、2 位剧情人物) | `art/biao/vector/<名字>.svg`,5~7 层 | 位图描出来的,按元素拆层 |
| 场景图(19 张) | `art/biao/vector/scene_*.svg`、`home_bg.svg`,2 层(远景与建筑、灯光) | 位图描出来的。场景里没有人物可拆,颜色分得比人物细,文件也大一些(每张 1.5~3 MB) |
| 图标(87 个) | `assets/biao/**/*.svg`,2 层(底板、图形) | `tools/build_biao_icons.py` 直接用路径画的,页面上用的就是这份矢量,不经过位图 |

界面上其余的部件(按钮、弹窗、页签、横幅上的字、底部导航)是用样式画的,本来就不是图片。


前两个第一次跑会从 Hugging Face 下载三个模型到 `.work/models/`(共约 300 MB)。都在 CPU 上跑,不需要显卡:
放大每张两三分钟,描矢量每张十几秒。需要的 Python 包:`onnxruntime`、`huggingface_hub`、`opencv-python-headless`、`vtracer`、`numpy`、`Pillow`。

## 4. 拆层是怎么判断的,哪里会不准

1. 先用抠图模型把人物从背景里分出来 → 「背景」层。
2. 头部一带交给**人脸解析模型**去认:皮肤(连耳朵、鼻子、脖子)→「皮肤」,眉眼嘴 →「五官」,头发 →「头发」。
   脸在哪取自 `art/biao/cast.json`。模型不看肤色,所以脸被霓虹光染成粉的、青的也认得出。
3. 几乎看不到脸的(主角、对手戴着面罩和头盔)→ 整个头部归「头盔与面罩」,不再分皮肤和头发。
4. 头发垂到头部范围以外的部分:取认出来的头发的主色,把颜色相近、又和头发连着的接上。手等露出来的皮肤同理。
5. 人物里很亮、很艳的品红和冰青 → 「霓虹光」(脸和头发上的不算)。
6. 剩下的里面很暗的 → 「暗部与线条」;其余 → 「服装」。

每张图分出了哪些层、各占多大面积,记在 `art/biao/vector/layers.json`。10 个人物里,8 个露脸的都有皮肤、五官、头发三层,2 个戴面罩的有「头盔与面罩」层。

已知会不准的地方:

- 人脸解析模型是拿真人照片训练的。我们的立绘偏写实,试下来分得准;换成很扁平的画风可能就不行了。
- 眼睛有时被算进「皮肤」而不是「五官」(凌),五官层里只剩眉毛和嘴。
- 垂下来的深色头发和深色衣服挨着时,接上的那段可能多拿或者少拿。
- 主角的面罩上方露着头发,也一起归在了「头盔与面罩」层。
- 场景不拆物体,只分「远景与建筑」和「灯光」两层。

这些都可以在矢量软件里把路径拖到正确的层来修。

## 5. 在 GitHub 上找到的,以及为什么这么选

| 项目 | 是什么 | 用没用 |
|---|---|---|
| `visioncortex/vtracer` | 把位图描成彩色矢量路径,速度快,有 Python 接口 | **用了**,每一层都是它描的 |
| `skytnt/anime-seg` | 二次元人物抠图模型 | **用了**,分背景和人物 |
| BiSeNet 人脸解析(`zllrunning/face-parsing.PyTorch` 的做法;用的是 Hugging Face 上 `bluefoxcreation/Face_parsing_onnx` 这份 ONNX) | 认出脸上每个像素是皮肤、眉、眼、嘴、头发还是帽子,共 19 类 | **用了**,头部的皮肤、五官、头发就是它分的。**注意**:这份 ONNX 的许可写的是 other,原始训练数据(CelebAMask-HQ)限非商业研究用途。我们只拿它当离线工具来决定「哪条路径放哪一层」,模型本身和它的输出都不进游戏;但上架前请法务确认这样用有没有问题,不行就换成下面那个 MIT 的 |
| `siyeong0/Anime-Face-Segmentation` | 专门给二次元人脸分割的模型(MIT):头发、眼、嘴、脸、皮肤、衣服 | 没用:只有 PyTorch 权重,要另装 PyTorch;是上面那个的备选 |
| `deepghs/cdc_anime_onnx`(CDC) | 二次元 4 倍放大模型,ONNX 格式,CPU 能跑 | **用了**,放大母版 |
| `xinntao/Real-ESRGAN`(anime 6B) | 最常见的二次元放大模型 | 没用:官方只给 PyTorch 权重和需要显卡接口的可执行文件,这台机器上装不上对应的 Python 包。效果和 CDC 是一个量级 |
| `xuer98/svgit` | 先用分割模型(FastSAM)认出一个个物体,再每个物体一个图层地描成 SVG | 思路照着学了(先分块再描);没直接用:它要装 PyTorch 和分割模型,体积大,而且通用分割模型对二次元人物的头发、皮肤分得并不稳 |
| `Picsart-AI-Research/LIVE-Layerwise-Image-Vectorization` | 研究级的逐层矢量化,出来的路径最少、最像手绘 | 没用:一张图要优化几十分钟到几小时,需要显卡 |
| `AHEKOT/ComfyUI_VNCCS` | 视觉小说立绘的整套流程:建角色、换装、换表情、出透明底立绘 | 没用:要本地跑 ComfyUI 和显卡。有显卡的话,这是做「同一角色多表情」最省事的路 |
| `fromtheexchange/image2svg-awesome` | 位图转矢量的工具清单 | 查资料用 |

## 6. 还能怎么提高

- **有显卡的电脑**:用 ComfyUI 直接出 2 倍以上的原图(而不是先出小图再放大),清晰度是真细节而不是「猜」出来的;再配 VNCCS 做多表情。
- **手工**:在 `art/biao/vector/` 的基础上,让美术重描脸和手的轮廓、把渐变换成真正的矢量渐变。
- **分得更细**:衣服现在是一整层。要把外套、内搭、配饰各自成层,得再接一个服装解析模型,或者由美术手动分。
