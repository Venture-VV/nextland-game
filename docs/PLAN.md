> 任何接手的人或 AI,先读完这一份再动手。做完一项就在「进度板」里打勾,并写上是谁做的。

## 1. 要做成什么

一个网页里有两套可以一键切换的系统,规则、数值、存档完全共用,只有美术不同:

| | 里 | 表 |
|---|---|---|
| 是什么 | 新生乐园世界现在线上的样子 | 全部美术重做的女性向版本 |
| 标准 | 和录屏越像越好 | 原创、抓眼、不甜、成熟有张力 |
| 素材来源 | 录屏 | 新生成并经过设计加工 |

另外两件事贯穿始终:**动效更出彩**,以及**多几种好玩的玩法**。

主页上有一个「表 / 里」开关,随时切换,切换时不丢进度。

### 业主的原话(判断有分歧时以此为准)

- 「明天的过审很看重,你能不能完美复刻现在的系统,你要先做到。」
- 「表就是升级的女性向风格的系统(只是美术不一致,其他不要改)。」
- 「不要太 AI 太抄袭,不要迪士尼……要够吸引眼球,不要甜美,可以擦一点边。」
- 「你能否多设计一些好玩的玩法。」
- 关于 Gemini 那一版:「太迪士尼了,而且也很抄袭恋与深空。」

## 4. 已经定下的事

每条后面写了理由。标「待业主确认」的先按默认做,业主说了不同意见就改。

1. **不合并 Gemini 分支。** 它的交接手册第一条是「对标《恋与深空》」,立绘提示词里直接写了那款游戏的名字,配色是粉紫珠光。业主已经否定这个方向;照着一款现成游戏的画风做也不合适。借鉴的只有三点:图文分离(字不烤进底图)、立绘舞台的互动层(呼吸、点触反馈、台词气泡不遮脸)、资产构建脚本的组织方式。它在 `js/data.js` 里给伙伴加的称号、档案、台词来源不明,不采用。
2. **表和里共用一份逻辑。** 皮肤只决定「画成什么样」。不允许出现 `if (皮肤 == 表) 规则不同`。验收办法:同一套走查在两种皮肤下各跑一遍,存档数值逐项相等。
3. **`js/data.js` 里已有的名字、ID、数值不改。** 只有拿到飞书文档后,把「补的」换成「真的」这一种改动例外,而且两种皮肤同时生效。
4. **里的战斗恢复成原版的自动对撞**(照录屏复刻),作为默认。3D 节拍对决保留,归到「扩展玩法」,由单独的开关控制,和皮肤无关。**待业主确认。**
5. **动效分两档。** 里用「原版」档:只做录屏里看得到的动效,时间照录屏量。表用「升级」档。两档共用一套底层套件。
6. **表的画风走「绯契」方向**(见第 7 节),先出 3 张定调图给业主看,通过了再批量出图。**待业主确认。**
7. **「擦边」的尺度**:所有可攻略角色都画成明确的成年人;靠剪裁、姿态、眼神、光影做张力;不出现裸露和性暗示动作。登录页挂着 16+ 的适龄标识,美术不能超过它。**待业主确认。**
8. **出图先用免费的**(见第 8 节),要花钱之前先问业主。
9. **双主角切换**(Gemini 手册里有)不做。它是新功能,不在「只换美术」的范围里。**待业主确认。**

## 6. 动效规矩(来自 yuzu 的动效套件)

1. 只动四样:透明度、位移、缩放、颜色。不动会引起整页重排的属性。
2. 不用匀速。进入用缓出;退出比进入快,约六成时间。
3. 进出成对。关掉时逻辑上马上卸掉,另留一份不能点的副本播完退场再删。
4. 方向一致。从哪边来回哪边去。
5. 只在出现时播一次。列表刷新不重播;一次最多带前 12 项依次出现。
6. 有反应。按下略缩,0.2 秒内,不挡操作。
7. 字要看得完。提示停留时间按字数算。
8. 系统开了「减少动态效果」就全部关掉。
9. 不加动画库。

| 名称 | 值 | 用在 |
|---|---|---|
| `--dur-micro` | 120ms | 按下、颜色 |
| `--dur-fast` | 180ms | 退场、页签滑块 |
| `--dur-base` | 260ms | 弹窗、提示、页面内容进场 |
| `--dur-slow` | 380ms | 大面板、折叠 |
| `--ease-out-soft` | `cubic-bezier(0.22, 1, 0.36, 1)` | 进场 |
| `--ease-out-expo` | `cubic-bezier(0.16, 1, 0.3, 1)` | 大面板 |
| `--ease-in-quick` | `cubic-bezier(0.4, 0, 1, 1)` | 退场 |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | 小元素回弹 |

这些是表「升级」档的默认值。里的「原版」档以录屏量出来的为准。

## 7. 表的画风提案

推荐 **A「绯契」**。B、C 是备选,定调图阶段可以各出一张对比。

| | 方向 | 样子 | 评价 |
|---|---|---|---|
| A | 绯契 | 黑色电影 × 时装大片 × 契约档案。墨黑、骨白、酒红、暗金,少量冷青。强明暗、硬边阴影。界面母题是契约、封蜡、签名、涂黑条、档案夹 | 推荐。游戏里本来就有「伙伴协议」「档案」「契约」,母题是长出来的不是贴上去的;成熟、不甜、有张力 |
| B | 霓虹浮世 | 平涂加版画线条,东方构图,靛蓝、朱红、荧光粉 | 最不像 AI 写实图,辨识度高;张力弱一些 |
| C | 镀铬白昼 | 白金属、镜面、解构时装,浅色高调 | 容易滑回「珠光浅色」那一路,不推荐 |

禁区,三个方向都适用:

- 不参照任何现成的游戏、动画、画师。提示词里不出现作品名和人名。
- 不要圆润甜美的大眼造型,不要粉紫珠光。
- 不要未成年人形象。顾轩在别处被写成「少年」,这里一律画成成年青年,且不做性感化处理。
- 不要裸露和性暗示动作。

「不要太 AI」靠四件事:先定设定图再出成品;统一的后期(调色、颗粒、印刷质感);图只是素材,最后的画面由版式、字体、线条这些设计元素来定;人工挑选,宁缺毋滥。

## 9. 新玩法的规则草案

| 玩法 | 怎么玩 | 奖励 | 接在哪 |
|---|---|---|---|
| 伙伴援护 | 节拍对决里,能量满时可以改放援护技:由当前信任等级最高的伙伴出手 | 无额外奖励,效果随信任等级提高 | 战斗 |
| 调频密码 | 三个旋钮对应波形的频率、振幅、相位,在 30 秒内把自己的波形调到和目标重合 | 阪神信用点、装备晶片 | 互动窗口 |
| 涂鸦暗号 | 九宫格依次亮起一串涂鸦,照顺序点回去;每过一轮加一格 | 好感道具箱 | 互动窗口 |
| 园区巡游 | 地图上每天 3 个光点;点到触发伙伴小事件,二选一 | 信任值 | 主页地图 |

数值在做的时候定,原则是不让新玩法的产出超过原有玩法一天的产出。

## 10. 怎么干活(对所有接手的人和 AI)

硬规矩:

1. 不引入构建步骤和框架。必须能双击 `index.html` 直接跑。
2. 改了脚本、样式、音乐,提交前跑 `python3 tools/stamp.py`。
3. 提交前跑 `node tools/walkthrough.cjs`,全过才提交。新功能要加进走查。
4. 不改 `js/data.js` 里已有的名字、ID、数值(第 4 节第 3 条的例外除外)。
5. 不合并 `feat/deepspace-wonderland-theme`。
6. 素材的来源要能说清:里的图只来自录屏;表的图记在 `docs/ART_PROVENANCE.md`。
7. 录屏里有账号的真实互动码和玩家编号,任何新素材里都不能带出来。
8. 做完一项,在下面的进度板打勾并写名字;发现计划不对,直接改这份文档并在 PR 里说明。

并行分工时的文件归属(避免互相覆盖):
