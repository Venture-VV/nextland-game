## 1. 要做成什么

一个网页里有两套可以一键切换的系统,规则、数值、存档完全共用,只有美术不同:

| | 里 | 表 |
|---|---|---|
| 是什么 | 新生乐园世界现在线上的样子 | 全部美术重做的女性向版本 |
| 标准 | 和录屏越像越好 | 原创、抓眼、不甜、成熟有张力 |
| 素材来源 | 录屏 | 新生成并经过设计加工 |

另外两件事贯穿始终:**动效更出彩**,以及**多几种好玩的玩法**。

主页上有一个「表 / 里」开关,随时切换,切换时不丢进度。

### 业主的原话(判断有分歧时以此为准)

- 「明天的过审很看重,你能不能完美复刻现在的系统,你要先做到。」
- 「表就是升级的女性向风格的系统(只是美术不一致,其他不要改)。」
- 「不要太 AI 太抄袭,不要迪士尼……要够吸引眼球,不要甜美,可以擦一点边。」
- 「你能否多设计一些好玩的玩法。」
- 关于 Gemini 那一版:「太迪士尼了,而且也很抄袭恋与深空。」

## 4. 已经定下的事

每条后面写了理由。标「待业主确认」的先按默认做,业主说了不同意见就改。

1. **不合并 Gemini 分支。** 它的交接手册第一条是「对标《恋与深空》」,立绘提示词里直接写了那款游戏的名字,配色是粉紫珠光。业主已经否定这个方向;照着一款现成游戏的画风做也不合适。借鉴的只有三点:图文分离(字不烤进底图)、立绘舞台的互动层(呼吸、点触反馈、台词气泡不遮脸)、资产构建脚本的组织方式。它在 `js/data.js` 里给伙伴加的称号、档案、台词来源不明,不采用。
2. **表和里共用一份逻辑。** 皮肤只决定「画成什么样」。不允许出现 `if (皮肤 == 表) 规则不同`。验收办法:同一套走查在两种皮肤下各跑一遍,存档数值逐项相等。
3. **`js/data.js` 里已有的名字、ID、数值不改。** 只有拿到飞书文档后,把「补的」换成「真的」这一种改动例外,而且两种皮肤同时生效。
4. **战斗默认用 3D 节拍对决**(业主 11 月 15 日定的)。照录屏复刻的原版自动对撞保留,在「设置」里关掉「3D 节拍对决」就换回去。战斗和动效的开关都和皮肤无关:业主说过表和里「只是美术不一致,其他不要改」,所以翻面只换美术。
5. **动效分两档。** 「原版」档只做录屏里看得到的动效(量过:弹窗和页面直接出现,只有提示滑入、奖励淡入、战力数字滚动)。「升级」档是 `docs/MOTION.md` 里那一套,**现在是默认**,在「设置」里可以关。两档共用 `js/motion.js`。算法依据是自己调研的,不是照搬 yuzu 的规范。
6. **表的画风:二次元精致立绘 + 赛博霓虹**(业主 11 月 15 日选的)。原先提的「绯契」(黑色电影海报风)出了两轮定调图,业主否了,理由是「不像游戏立绘」。新方向的做法见第 7 节。定调图要业主点头后再批量出图。
7. **「擦边」的尺度**:所有可攻略角色都画成明确的成年人;靠剪裁、姿态、眼神、光影做张力;不出现裸露和性暗示动作。登录页挂着 16+ 的适龄标识,美术不能超过它。业主 11 月 15 日同意。
8. **出图先用免费的**(见第 8 节),要花钱之前先问业主。
9. **双主角切换**(Gemini 手册里有)不做。它是新功能,不在「只换美术」的范围里。**待业主确认。**

完整内容在 `docs/MOTION.md`:学了哪些地方、八条原则、时长与曲线、十八个算法(弹簧、二阶跟随、依次出现、布局过渡、退场影子、像素块转场、滚动数字、震屏、顿帧、挤压拉伸、预备动作、粒子、倾斜与全息卡、磁吸橡皮筋惯性、文字效果、流光描边、抽卡编排)、两档各开哪些、怎么验收。

- 用弹簧而不是固定时长的补间,动到一半能改目标。
- 原版战斗里角色出场和被击破就是像素块,所以像素块转场是游戏自己的语言,用到页面切换和表里翻面上。

## 7. 表的画风

**定了的方向:二次元精致立绘 + 赛博霓虹。** 2D 半厚涂,人物漂亮、线条利落,机能风服饰,霓虹轮廓光;成熟、带一点危险感,不甜。界面配色是夜色玻璃 + 玫红霓虹 + 冰青,配香槟金细线(已经做成 `css/skin-biao.css`)。

**否掉的方向(不要再试):**

- 「绯契」:黑色电影 × 时装大片,平涂色块加硬阴影。出了两轮,业主的评价是「不像游戏立绘」——更像欧美漫画封面或海报。
- 偏写实、照片感的:就是「太 AI」的样子。
- Gemini 分支那一路:圆润的 3D 感,被评价为「太迪士尼」「很抄袭恋与深空」。

**「像游戏立绘」的做法**(业主让去 GitHub 上找速成的路子,查到的要点):

- 用二次元专用的模型(Illustrious / NoobAI 一系),提示词写成逗号分隔的标签,不写整句话。顺序:人数 → 动作姿势 → 外貌服饰 → 背景 → 构图与画风 → 质量词放最后。依据是 bex 的 Illustrious 入门指南(`bextoper.github.io/bex-s-Stable-Diffusion-and-Illustrious-Guide`),它给的参数是 832×1216、28 步、CFG 5、DPM++ 2M Karras。
- 立绘和插画的区别在构图:**单人、站姿、半身到大腿或全身、纯色背景**。出图后抠掉背景,再叠到我们自己的界面背景和版式上。场景另外画。
- 一个角色先定一张设定图(正面、几个表情、几套衣服),之后的图都以它为参考,才不会每张长得不一样。视觉小说圈有一整套现成流程:`AHEKOT/ComfyUI_VNCCS`(先建角色,再出服装、表情,最后出透明底的立绘)。它要在本地跑 ComfyUI,需要显卡,这个云端环境跑不了,但流程照着学。
- 这类模型主要靠「画师名」控制画风。**我们不用画师名、作品名**,只用画法类的标签(上色方式、线条、光影)加上选模型来定风格,避免照着某一位画师或某一款游戏。

禁区,三个方向都适用:

- 不参照任何现成的游戏、动画、画师。提示词里不出现作品名和人名。
- 不要圆润甜美的大眼造型,不要粉紫珠光。
- 不要未成年人形象。顾轩在别处被写成「少年」,这里一律画成成年青年,且不做性感化处理。
- 不要裸露和性暗示动作。

「不要太 AI」靠四件事:先定设定图再出成品;统一的后期(调色、颗粒、印刷质感);图只是素材,最后的画面由版式、字体、线条这些设计元素来定;人工挑选,宁缺毋滥。

## 8. 出图工具

实际试下来的情况(11 月 15 日):

| 工具 | 结果 |
|---|---|
| Pollinations(匿名) | 匿名只给一个通用模型,出图偏写实、带水印,不合用;后来再请求直接返回「服务不可用」和「需要付费」 |
| Stable Horde(匿名) | 能用,模型多。通用模型(AlbedoBase XL)出图正常,但每 3 张要排 9~14 分钟,有时超时。二次元模型(Nova Anime XL)出的图被它的内容过滤器整张替换;过滤器不能关(也不应该关),只能把提示词写得更规矩再试 |
| Cloudflare Workers AI | 没试:要业主注册账号并给密钥。每天有免费额度,比上面两个稳,没有水印 |
| 本地 ComfyUI | 没试:要一台带显卡的电脑。质量和可控性最好,也是 VNCCS 那套立绘流程需要的 |
| CellCog(已连接) | 没试:免费档余额 300 点,每次花多少要试了才知道,用之前先问业主 |

脚本在 `.work/art/horde.py`(不进仓库),每一轮的提示词和种子在各自目录的 `jobs.json`。

顺序:先用免费的做定调图。批量阶段如果免费的质量或速度不够,把需要的额度报给业主,同意了再用。

许可与披露:开源模型出的图一般可以商用,但各模型的许可不同,上架前请法务核对 `docs/ART_PROVENANCE.md`;AI 生成的美术在一些平台需要披露。
